# Domain docs

This is a single-context repository.

Before exploring a domain area, read `GLOSSARY.md` at the repository root if it exists and read ADRs under `docs/adr/` that touch the area. Missing domain files are acceptable; create them only when the domain vocabulary or a durable design decision needs to be recorded.

Use the glossary's vocabulary in issue titles, tests, and implementation discussions. If a change conflicts with an existing ADR, call out the conflict explicitly before proceeding.

Expected layout:

```text
/
├── GLOSSARY.md
└── docs/adr/
```
